# 目录标准：每类目录放什么/不放什么

> 结构提炼自实际项目 docs 体系。根目录固定四件：`README.md`（导航）、`AGENTS.md`（AI 路由）、`TODO.md`（待办）、以及六个内容目录。

## conventions/ — 强制开发规范

**放**：各领域"必须遵守"的规范，编号命名（`00-`、`01-`、`02-`…，分册用字母后缀 `02a-`、`02b-`）。编号从 `00-项目配置.md` 开始，它是**唯一变量入口**。

**不放**：操作指南（→ `guides/`）、设计文档（→ `specs/`）、一次性决策（→ `adr/`）。

**命名模式**（实例）：`02-后端工程结构与类命名规范.md`、`03-API规范.md`、`04-数据库规范.md`、`08-Git规范.md`。编号稳定后不重排——外部引用（AGENTS.md/索引）按编号路由。

## specs/ — 设计规格

**放**：架构规划、领域边界、服务详设、横切设计。按架构层级分子目录（一种实践是 TOGAF 分层：`architecture/`（含 `application/`、`cross-cutting/`、`governance/`）、`domain/`、`services/`（每服务一目录）、`ops/`）。子目录按项目自身架构分层增建，不必照搬 TOGAF 六层。

**文件命名（❌ 禁止违反）**：`L{层级}-{NN}{分册字母}-{主题}.md`——**层级字母（序号字母）在 NN 前**，看文件名即知"哪个层级 → 哪个分类 → 是否有配对实现/兄弟子文档"：
- **`L{层级}`**：一位层号前缀。参考映射（TOGAF 对齐）：`L0` 项目管理 / `L1` 架构愿景 / `L2` 应用架构 / `L3` 技术架构 / `L4` 详细设计（services/）/ `L5` 实现规范 / `L6` 部署运维。**层级字母 ↔ 子目录的映射由项目自定**，写入 specs 入口 README；若项目已有占用 `L{N}` 的语义（如产品能力分层 L0~L7），**必须换前缀字母**避免双义
- **`{NN}`**：层级内两位递增（01→02→03…），代表不同主题分类；新增主题追加下一个数字，不影响已有编号
- **分册字母**（字母在 NN 后、主题前）：概述+实现配对共享数字，实现版加 `i`（`L2-01` / `L2-01i`）；同专题兄弟子文档接 `j`/`k`/`l` 按序（`L3-11` 基号 + `L3-11i` 实现 + `L3-11j`/`L3-11k` 兄弟子能力）；同号多份并行文档须在所属目录 README 显式标注「同属 Lx-NN 专题」
- 主题直接写内容（"领域模型与动作模型"，不写"关于领域模型的讨论"）；子目录只承载物理分组，**禁止**在文件名里再加类型前缀（`DESIGN-`/`PROPOSAL-`/`ARCHITECTURE-` 等——类型混乱、编号各自为政是真实事故）
- 编号稳定后不重排；跨子目录引用必须带 `L{层级}-{NN}` 前缀（如 `L3-11i`），同层内可省略层级段

**不放**：强制性编码规范（→ `conventions/`）。

## adr/ — 架构决策记录

**放**：`ADR-编号-标题.md`，一文件一个决策。标题直接写结论（实例：`ADR-001-库存扣减走Redis预扣而非Seata.md`——标题即决策，不写"关于库存的讨论"）。

**不放**：决策的实施细节与代码（→ `specs/`）。

## guides/ — 操作指南

**放**：开发者上手指南、CI/CD 流水线、测试策略、标准代码生成提示词、敏感字段清单、`template/`（可复制样例）。

**文件命名**：`NN-主题.md`，NN 为 guides 目录内递增编号（guides 数量少，无需全局编号）；分册规则同 conventions/（`01a-`、`01b-` 字母后缀）。

**不放**：强制规范正文（→ `conventions/`）。

## plans/ — 交付计划

**放**：排期、里程碑、Go/No-Go 结论。文件名带自然周期（实例：`{年月}-架构交付计划.md`）。

**不放**：长期有效的规范——计划会过期，规范不会。

## scripts/ — 文档配套协作脚本

**放**：多仓批量拉取/硬同步（实例：`pull-all.sh`、`sync-hard.sh`）、文档链接存在性检查（`check-backtick-paths.ps1`）。

**不放**：业务代码。

## 根目录三件

- **`README.md`**：文档导航——层级/目录表 + "开发前必读"清单（指向 `00-项目配置.md` 与 `规范索引.md`）+ 架构治理入口。不放规范正文。
- **`AGENTS.md`**：AI 进场路由——编号任务 → 必读文件。只指路，不复制规范内容（否则路由与规范会出现两个事实来源）。
- **`TODO.md`**：执行待办清单。与缺口清单互补：TODO 管"要做"，缺口清单管"缺不缺"。

## 判断口诀

一份新文档不知道放哪时问三个问题：

1. 它是"必须遵守的约束"吗？是 → `conventions/`（编号入册）
2. 它是"一次决策及其理由"吗？是 → `adr/`（编号入册）
3. 其余按用途：怎么做 → `guides/`；长什么样 → `specs/`；什么时候做 → `plans/`
