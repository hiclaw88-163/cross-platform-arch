# 治理规则

> 提炼自实际项目 docs 的治理实践（README 导航声明、规范索引冲突声明、TODO 双轨、链接校验脚本）。

## 1. 单一事实来源

| 内容类型 | 唯一来源 |
|---|---|
| 项目特定变量值（名称/包名/版本/前缀/机器相关路径） | `conventions/00-项目配置.md` |
| 某主题的强制规则 | `conventions/` 对应编号文件（frontmatter 写明"唯一源"） |
| 决策及其理由 | `adr/` 对应编号 |
| 任务→文档的路由 | `conventions/规范索引.md` 与 `AGENTS.md` |

违规表现：同一约束在两份文档里各写一遍（版本信息漂移）、AGENTS.md 复制规范正文（路由与正文脱节）。修复：删副本、留指路。

## 2. 冲突优先级

冲突必须**显式声明**而不是默认隐含。每份规范开头声明自己的优先级（标准模式）：

> 冲突时：本文 > 上级摘要 > 通用模板默认值。

体系级顺序（由各文件声明串起来）：`conventions/` 项目覆写 → `specs/` 架构规划 → 通用模板默认值。发现两份 must 文档实际冲突时：修低优先级文档并升版，不允许"两份都对"。

## 3. 升版纪律

- 文档内容变更必须升 frontmatter `version`；外部引用按"以 xx v1.11 为准"锁定版本号（AGENTS.md 路由声明模式）
- 规范改名/拆分（如 `02` 拆出 `02a/02b/02c`）时：同步更新 `规范索引.md` 快速路由表与 `AGENTS.md` 编号路由
- 文档描述与实现不一致 → **先改文档再动代码**；改了代码不改文档视为未完成

## 4. 链接与引用有效性

- 正文中所有 `` `path` `` 反引号引用应能通过存在性检查（实践：`check-backtick-paths` 类脚本全库扫描，失效即修）
- 目录改名/文件移动后，先跑一遍链接检查再提交
- 跨 docs 仓引用（如文档仓引用部署仓）写明所属仓前缀，避免误判失效

## 5. 待办双轨

- `TODO.md` 管"**要做**"（执行待办，勾选推进）
- 缺口/评审清单（`specs/` 下）管"**缺不缺**"（架构缺口 P0/P1/P2 跟踪）
- 两边互指不互抄；TODO 完成后在对应缺口清单回填状态

## 6. AI 协作纪律

- AI 进场第一步读 `AGENTS.md`，按编号路由取规范，不从记忆里"默认"生成
- 生成代码前过规范检查清单；遇到规范未覆盖的场景，先补规范（留 ADR）再生成，而不是绕过
- 规范中出现 ❌ 禁止项即硬约束，AI 不得以"上下文需要"为由违反
