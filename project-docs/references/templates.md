# 各类文件写法纪律

> 全部提炼自实际项目 docs 的文件写法。配套模板见 `templates/`。

## 00-项目配置.md — 唯一变量入口（最高优先）

所有项目特定值（项目名、根包、组织标识、技术栈版本、API 前缀…）**只在此文件**给出实际值；其余任何文档引用这些值时一律写 `{占位符}`，生成/移植时由本文件替换。

- frontmatter：`name: {project}-project-config`、`description`（说明它是变量唯一入口）、`version`
- 正文三节：基础信息（{project}/{projectName}/{basePackage}/{company}/{author}）→ 技术栈变量表（按项目增删，如版本号、前缀）→ 工程目录说明
- 开头声明："移植/改名时**只改本文件**"
- 该文件引用技术栈细节时指向 `specs/` 下对应文档，不在配置里展开版本策略

## conventions 规范正文（编号文件）

frontmatter 四键（编号命名空间规范的标准模式）：

```yaml
---
name: {project}-{topic}
description: {主题约束一句话}。TRIGGER when <何时加载本规范>；DO NOT TRIGGER when <何时不加载>
version: "1.1.0"
level: must
---
```

正文骨架（编号规范的标准结构）：

1. **唯一源声明 + 冲突优先级**："> **唯一源**：本主题以本文为准。冲突时：本文 > 上级摘要 > 通用默认。"
2. **总原则（❌ 禁止违反）**：编号列出不可破的铁律
3. **分类细则**：后缀表/命名表等，用表格给出"类型 → 正确形态 → 禁止形态"
4. **已定稿对照表**：废弃名 → 现行名（防止 AI 用旧习惯生成）
5. **检查清单**：生成代码前逐项过

写作纪律：`level: must` 的文件出现"推荐/建议"字样要审慎——要么升为禁止，要么降级 `should`。

## conventions/规范索引.md — 按任务路由

三段式（规范索引的标准结构）：

1. **frontmatter + 关系声明**："> **关系**：本目录 = {project} 覆写与落地约定，自包含。冲突时：本目录 + 架构规划文档优先于通用模板默认值。"
2. **使用前必读**：编号步骤，第 1 条固定为"先读 `00-项目配置.md`（唯一变量入口）"
3. **快速路由表**：`| 你要做什么 | 读哪篇 |`——一行一个开发任务，指向具体编号文件。表要覆盖团队高频任务，AI 与人共用这份路由

## AGENTS.md — AI 进场路由

结构（AGENTS.md 的标准模式）：

1. 标题 + 一句总纲："写代码或改文档前："
2. **编号任务路由**：每个编号 = 一类任务 → 必读文件。第 1 条固定为"读 `conventions/00-项目配置.md`"。路由要点格式："**起模块/起服务名**：读 `01`；**写代码/起类名**：读 `02`（分册 `02a/02b`）"
3. **收尾**：遵守规范中 ❌ 禁止项；通用模板已内聚于 conventions/，不再引用外部 skillSource（或列出外部依赖）
4. **存放规则**（如项目有跨工作区隔离要求）：写一条声明，值放 `00-项目配置.md` 变量，**不写死磁盘路径**

纪律：AGENTS.md 只指路不复制内容；规范改名/拆分后必须同步更新路由编号。

## adr/ADR-编号-标题.md — 架构决策记录

- 命名：`ADR-{三位编号}-{结论式标题}.md`（标题即决策："走 Redis 预扣而非 Seata"，不是"关于库存的讨论"）
- frontmatter：`name: {project}-adr-{编号}`、`description`（一句话决策 + TRIGGER）、`version`、`level: must`
- 头部四行：**状态**（Proposed | Accepted | Superseded by ADR-xxx）、**日期**（`{date}` 占位）、**决策者**（`{owners}`）、**关联**（相关文档编号）
- 三段正文：**背景**（问题与候选方案）→ **决策**（选定方案 + 流程要点，可编号）→ **后果**（**正面** / **负面或约束**，必须两面都写）
- 决策被推翻时不删除：状态改 `Superseded by ADR-xxx`，新建编号

## TODO.md — 执行待办

- 开头声明双轨关系："> 本清单管「要做」，缺口清单管「缺不缺」，互补。"
- 按 P0/P1/P2 分节；条目带勾选框；完成一项勾一项
- 大事项下挂子条目记录"决定/已执行/结果"，保留过程证据（TODO 模式：勾选后写"✅ 已采用 xx，共清理 N 处"）

## 反引号路径引用

规范与计划中所有 `` `path/to/file` `` 引用要能通过存在性检查（可用 `check-backtick-paths` 类脚本实践）。引用其他目录文件时用相对路径；跨 docs 仓引用要写明所属仓。
