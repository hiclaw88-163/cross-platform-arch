# 02 · 开发红线（❌ 禁止违反）

> **唯一源**：本主题以本文为准。
> 冲突时：本文 > 上级摘要 > 通用默认。
> §1 前六条是「一核多端」家族默认红线（提炼自 cross-platform-design R1-R9 与
> 实测事故，配套门禁 `verify_project.py` 机器拦截）；项目特有红线追加于 §1 末条
> 之后，删除默认条目前先确认门禁不再依赖它。

## 1. 总原则（❌ 禁止违反）

1. **端零映射**：端上禁止 `if status in [...]` 式语义映射表；UI 只消费 core
   出产的 `kind` 谓词。判断口诀："这个业务规则改一下，要改几个文件？"
   超过 1 个（core 之外）→ 没归位。
2. **core 纯净**：`packages/core` 零框架依赖（FastAPI/Typer/SQLAlchemy/
   Pydantic 等不得 import）。
3. **契约先行**：server 改 API → 重新生成 `packages/sdk`（openapi.sha256 必须
   同步）；web 端 DTO 字段形状**必须派生自** SDK 生成物（`Omit<Contract[...]>
   & { signal: Signal }` 范式，嵌套字段同样窄化），禁止手写字段清单——
   vue-tsc（门禁第 9 项收编）拦截漂移。
4. **显式报错不静默兜底**：配置非法/能力不支持 → 拒绝执行并如实上报，
   绝不静默降级；没有 try/except 吞错。
5. **设计 token 唯一来源** `apps/web/src/styles/tokens.css`；审美决策写进
   `docs/design-decisions.md`，不许散落组件。
6. **每次实质提交后跑门禁**：`{gate-cmd}` 全绿。
7. （项目特有红线追加于此：一条一行，写清判断口诀）

## 2. 检查清单

- [ ] 业务规则改动只落在 `packages/core`（端零映射）
- [ ] core 未 import 任何框架
- [ ] 改过 API → `packages/sdk` 已重新生成且 openapi.sha256 同步
- [ ] web DTO 字段形状派生自 `packages/sdk` 契约（types.ts 无手写字段清单）
- [ ] 没有 try/except 吞错静默降级
- [ ] 样式只用 `tokens.css` 里的 token
- [ ] 门禁全绿（`{gate-cmd}`）
