# 提交信息规范（Conventional Commits 简化版 · 强制）

格式：`<type>:[<需求单号>]: <中文主题>`（需求单号标记可选），type 是提交的唯一
标识，`git log --oneline` 一眼可辨。

## 需求单号标记（两种形式均可）

- `feat: 新增任务业务域`——不关联需求的日常改动（等价 `feat:[0]: …`）
- `feat:[OMS--958]: 任务采集批量上报`——关联需求单
- 单号规则：系统前缀 `--` 编号（`OMS--958`、`ERP--12`，字母数字均可）；`]` 后的冒号可省（`feat:[OMS--958] 任务采集`）
- 可与 scope 叠加：`fix(bridge):[OMS--777]: 修复推送丢失`

## type 对照表

| type | 用途 | 示例 |
|---|---|---|
| `feat` | 新功能 | `feat: 配置按环境分文件` |
| `fix` | 缺陷修复 | `fix: TID 模式下重复标签未去重` |
| `refactor` | 重构（不改行为） | `refactor: 统一响应构造` |
| `docs` | 文档 | `docs: 补充联调结论` |
| `chore` | 工程/杂务（不碰 src） | `chore: 统一依赖版本注释` |
| `build` | 构建脚本/依赖 | `build: 升级工具链版本` |
| `test` | 测试 | `test: 补仓储用例` |

## 规则（❌ 违反即提交失败或回拆）

1. **主题单行、动词开头、≤30 字、不加句号**；正文仅说明"为什么"（动机/取舍），禁止通篇大论
2. `scope` 可选（模块名），不强制
3. **一次提交一个意图**：禁止把无关改动混入同一提交；发现夹带先拆分再提交
4. 提交前必须 `git status` + `git diff` 改动项全覆盖（一次提交一个意图）；临时文件不入库
5. merge/revert 由系统生成的提交（`Merge branch …` / `Revert "…"` 开头）豁免本格式

## 强制校验（机器判定）

仓库内置 `commit-msg` 钩子（`.githooks/commit-msg`），不符合格式的提交直接拒绝：
- 随 `pnpm install` 自动启用（`git config core.hooksPath .githooks`）
- 未跑 install 的环境手动启用一次：`python scripts/install_hooks.py`

## 冲突优先级声明

本文 > 上级摘要 > 通用默认；与 `08-` 系列其他规范冲突时以本文为准。
